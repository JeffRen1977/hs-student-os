# High School Student OS — 竞争力评估与产品验证 v0.2

更新：2026-10-29。按 [架构建议](STUDENT_OS_ARCHITECTURE_RECOMMENDATIONS.md) 调整产品优先级，与 [产品方案](HIGH_SCHOOL_STUDENT_OS.md) 和 [实施计划](IMPLEMENTATION_PLAN.md) 的 M0–M5 一致。

证据范围：这是产品策略分析，不是本轮重新完成的市场调查。旧版中的价格、用户量、课程数量、供应商合作关系与具体功能缺少可追溯来源，本版不将其作为已核验事实或定价依据。后续市场调研须记录 URL、访问日期、地区/套餐和原文支持范围。

## 1. 核心假设：协调学习安排能否产生可感知价值

长期愿景是一个课程平台：第一方与第三方作者以数据形式发布 AP、SAT 等课程，学生在同一工作台里学习、获得评估并统一安排时间。首个试点使用 Calc BC 加 Digital SAT（通过作者发布流程制作）；不把“五门 AP + 全 SAT + 自动选校”作为同时上线条件。

待验证的价值主张：

> 完成一次练习后，系统能解释你哪里需要帮助、推荐有证据支持的下一项任务，并把它安排进你实际有空的时间。

这项价值不需要等待四年数据才开始验证。一次课程评估和适当的课程内短诊断即可检验建议是否有用；第二门课程能否只靠数据上线，则检验平台对作者的价值；长期记录能否进一步提高效果，需要后续真实使用数据支持。

## 2. 竞争参照与需验证的问题

以下是研究对象和比较维度，不是对竞品当前能力、价格或缺口的确定结论。

| 类别 | 研究对象示例 | 应核验的问题 | 对 Student OS 的设计启发 |
|---|---|---|---|
| 学科/考试辅导 | Khan Academy、Khanmigo、Bluebook | 反馈方式、练习覆盖、学习计划和实际可用范围 | 先把小范围题目的反馈和证据做好 |
| AP 内容与练习 | Fiveable、UWorld、Albert | 当前科目覆盖、rubric 评估质量、题目来源、教师工作流 | 学科包数量不能替代题目与评估质量 |
| 选校与申请 | CollegeVine、Kollegio、ESAI、Trajecta | 数据来源、访谈/文书边界、任务规划、服务模式 | 后续加入有来源的申请辅助，避免复制未验证功能清单 |
| 校内流程 | Scoir、Naviance、MaiaLearning | 学生/家长/顾问权限、学校采购与任务协作 | 独立身份和明确摘要权限要先定义 |
| 通用 AI 助手 | 常见聊天助手 | 用户完成同一学习任务所需时间、反馈准确性与后续安排 | 比较完整学习流程的结果，而非模型名称 |

当前不声称任何对手“没有课程平台”或“没有主动任务”。差异化要通过同任务比较与学生试用验证。

## 3. 首个试点必须证明的五件事

| 假设 | 验证方法 | 失败信号 |
|---|---|---|
| 反馈值得信任 | 审阅答案集逐项对 rubric，检查证据引用 | 输出流畅但评分依据错误 |
| 课程只靠数据即可上线 | 第二门课程完全通过课程包与审核流程制作，记录作者用时与遇到的平台缺口 | 需要为该课程改平台代码，或作者无法独立完成课程包 |
| 课程内后续建议恰当 | 多次独立错误 → 课程内短诊断 → 支持/不支持分支 | 一次错误直接被当成弱点 |
| 计划减轻协调负担 | 学生解释推荐原因，比较手工规划和系统建议的修改量 | 持续超配、重复任务或建议难理解 |
| 系统能融入日常 | 后续练习完成、独立题表现、返回使用和提醒撤销情况 | 会聊天但学生不愿做下一项任务 |

同时要求技术可靠：作答不丢失、重复请求不重复加进度、跨学生数据不串、断线后可恢复。未校准预测分上涨不计作学习成果；聊天轮数也不能直接当作学习效果。

## 4. 产品优先级：先完整闭环，再增加覆盖

### P0：M0–M4 的窄范围试点

1. 独立登录、学生数据隔离、持久 Task/Session/Run 和可靠提交。
2. 一门 Calculus 的可审阅题目、真实反馈、提示记录和证据回写。
3. 一个经验证的 AP→SAT 共享前置技能诊断与补强路径。
4. 学生时间预算、解释、延后/跳过/锁定安排和刷新恢复。
5. 选择一个 opt-in 提醒渠道，遵守时区、安静时段和频率限制。
6. 一次短诊断可作为邀请试点入口；是否免费、如何转化由试点验证，不先推出覆盖全部考试的漏斗。

全长模考、五科上线和家长商业看板不再是 P0 前提。小范围真实体验比用模拟分数展示完整产品更能验证价值。

### P1：M5 中按需求选择的扩展

- APUSH 优先，随后扩充其他 AP 的 MCQ/FRQ；每科权重与形式按其有效考纲核验，不假设所有科目同一比例。
- 当题库覆盖与评分可靠性足够时扩大全长/模块练习；官方式分数展示另需校准。自适应训练不等于官方评分算法。
- 学生授权的家长进度摘要；默认不共享完整对话、原始作答或文书。付费关系不自动扩大数据权限。
- 访谈式申请准备、活动事实确认、各校 supplement 管理；学校截止以官方来源核验，Common Data Set 不是所有最新截止日期的替代来源。
- 日历导入、净价/奖学金资料、人工反馈选项；先验证真实需求与来源维护成本。

### P2：后续渠道与技术选项

- 教师/顾问小规模合作测试，先人工验证获客假设，再决定是否开发多角色后台。
- PSAT/ACT、夏校/科研、模拟委员会等作为独立需求评估，不承诺只改 manifest 即可交付。
- MCP 分发、额外模型路由、Jev、Temporal、向量检索按测得的效果与工程需求引入；不是竞争优势的默认前提。
- 预测分校准报告：数据足够后评估预测与独立结果，记录适用范围和误差；不足时保持 unavailable。

## 5. 冷启动、内容与分发

冷启动先收集课程、目标、时区和可用时间，用小范围已审题确定学习起点。证据不足就推荐诊断，不虚构长期 mastery。学校日程可先由学生确认输入，导入是后续降低录入成本的改进。

内容是持续成本：题目、答案、rubric、后续规则与评估集都需要版本和审核，由课程作者承担、平台审核把关。新科目可能需要新画布、OCR 或沙箱等平台能力；这些作为平台能力一次实现后供所有课程选用，但不能把全部成本描述成增加一个文件。

分发先以少量学生/教师访谈和自愿试用测量获客来源、完成第一项练习的比例、后续任务完成与留存；涉及未成年人作品时按既定权限保存和展示。渠道实验不意味着提前承诺大型 Counselor 产品。

## 6. 商业假设与决策依据

本版不沿用未经核验的竞品价格、所谓纯 AI 客单上限或 Student OS 合理售价。先记录每次有效评估成本、内容维护成本、每周真实使用量和学生/家长付费意愿，再测试明确的套餐假设。

家长可能付费，学生实际使用，两者都需要价值验证。可展示有依据的学习进度、任务完成与时间安排，不以推测的录取概率或无校准分数制造付费压力。

扩大范围之前回答：学生是否完成了有用的下一步，推荐是否优于无上下文的普通聊天，新增科目是否值得其内容与支持成本。结果应回写 M5 排序，而不是把旧竞品功能表直接转成首发需求。
